# HUBARIO — RAW OS Deployment Identity

## Purpose

Hubario is the deployment-facing identity for the RAW OS prototype inside the `alask` repository.

Hubario does not replace RAW OS. RAW OS remains the governance and operating-system framework; Hubario is the product/application identity through which the prototype is experienced, tested and eventually deployed.

## Positioning

`RAW OS Core → Hubario Runtime → Domain Configuration → User / Actor Experience`

## Initial Pilot

**Domain:** Abang Sayur Pilot

**Primary test actor:** Actor 1 — Pioneer

## Prototype Scope

- Actor and role management
- Bounded authority
- Credit limits and exposure
- Geographic scope
- Permission checks
- Transaction validation
- Blocked / void states
- Compliance review and escalation
- Evidence preservation
- AI explanation and recommendation
- Human approval workflow

## Governance Boundary

Hubario must not:

- grant authority outside configured governance;
- increase credit limits without authorised approval;
- expand geographic scope without permission;
- delete governance evidence;
- bypass controls through UI or AI;
- treat AI recommendations as authoritative decisions.

## Test Principle

A Hubario deployment is considered valid only when the runtime enforces RAW OS rules rather than merely displaying them.

## Status

Prototype / controlled deployment identity. Not production-ready.
